# sav2adl — конвертер метаданных SPSS (.sav) в структуру переменных mtools

Скрипт читает файл данных SPSS (имена переменных, типы, метки переменных и метки
значений вместе с самим массивом данных) и выгружает конфигурационный файл
структуры `.adl` плюс набор справочников `.smt` для системы автоматизации
обработки анкет mtools.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python sav2adl.py                     # откроется системный диалог выбора .sav
python sav2adl.py data.sav            # консольный запуск, диалог не всплывает
python sav2adl.py data.sav --utf8     # выгрузка в UTF-8 вместо ANSI
python sav2adl.py data.sav --categorical QB3,QC1
```

Результат складывается рядом с исходным файлом: `data.adl` и справочники
`<база>.smt`. Первой строкой `.adl` идёт `include data.def`, затем пустая строка.

### Ключи командной строки

| Ключ | Назначение |
|---|---|
| `--utf8` | выгружать `.adl`/`.smt` в UTF-8 (по умолчанию ANSI / Windows-1251, `errors="replace"`) |
| `--encoding CP1251` | принудительная кодировка чтения `.sav` (по умолчанию автоопределение с перебором cp1251 / utf-8 / cp1252 / koi8-r) |
| `--categorical QB3,QC1` | базы категориальных гридов в дополнение к константе `CATEGORICAL_GRID_BASES` |
| `--user-missing` | читать пользовательские пропуски как значения, а не как `NaN` |
| `--quiet` | не печатать отчёт |

## Что делает скрипт

### 0. Формат блока

```
["S2. Укажите Вашу основную специальность." where=QS2
"Ревматология"=1
"Другое"=2
]
```

Закрывающая скобка идёт отдельной строкой после всех альтернатив, альтернативы
и `include` пишутся без табуляции.

### 1. Предварительная фильтрация

* служебные переменные выгрузки (имя начинается с `sys_`, см. константу
  `SERVICE_PREFIXES`) в `.adl` не попадают;
* переменная, у которой во всём файле нет ни одного заполненного значения
  (только системные пропуски / пустые строки), исключается из выгрузки;
* текстовые переменные (тип `A`) исключаются, **кроме** тех, что заполнены
  исключительно числами (коды регионов, ID) — такие сохраняются и дальше
  обрабатываются как числовые.

### 2. Нормализация комплексных имён

| Исходное имя | Нормализованное |
|---|---|
| `QA6_5.2` (5 — подпункт, 2 — строка) | `QA6xr2_5` |
| `QA12_r8_c2` (r8 — строка, c2 — колонка) | `QA12xr8_2` |
| `QA1_r1` (`<ПЕРЕМЕННАЯ>_r<ПОЗИЦИЯ>`) | `QA1xr1` |

Переменные с одинаковой базой и разным числовым суффиксом в конце
(`QA6xr2_1`, `QA6xr2_2`) схлопываются в одну запись множественного выбора
`QA6xr2`.

**Исключение — одиночные гриды.** Если у комплексной переменной нет пары
(`QA8_r1_c1` есть, а `_c2` нет), она не становится блоком множественного
выбора: имя откатывается к одиночной строке грида `QA8_r1` и дальше
канонизируется в `QA8xr1`.

### 3. Заголовки

* из меток SPSS удаляются технические префиксы `Имя_переменной - ` и
  `[База_грида] - ` (повторно, пока они есть);
* человеческий номер вопроса, оставшийся после очистки (`A1. В среднем...`),
  сохраняется как есть;
* для гридов (`_rN`, `xrN`) индекс строки генерируется автоматически:
  `B7.1. Хумира (адалимумаб)`, техническая буква `Q` в начале отсекается;
* номер вопроса, продублированный в тексте метки следом за сгенерированным
  индексом, убирается: `A1.1. A1. В среднем...` → `A1.1. В среднем...`;
* для одиночных переменных, у которых метка начиналась с собственного имени
  (`QS5x1 - Ревматоидный артрит`), индекс принудительно возвращается в
  человеческом виде: `["S5.1. Ревматоидный артрит" where=QS5x1]`.

### 4. Блоки ответов

| Сценарий | Формат |
|---|---|
| Обычные закрытые вопросы, множественный выбор | `"Метка"=код` — без `value=` и без `"Среднее"=m` |
| Открытый числовой вопрос без меток значений | `"18"=18 value=18` по уникальным значениям из данных + `"Среднее"=m` в конце |
| Категориальные гриды (`CATEGORICAL_GRID_BASES`) | `"Метка"=код` без аналитики |
| Остальные гриды — шкалы | чистая шкала, затем спецкоды, затем `"Среднее"=m` |

Спецкод — это код `>= 90` либо метка со стоп-словом: *затрудняюсь, отказ,
трудно, сложно, не знаю, other, другой*. Чистая шкала — последовательные коды
`1..K` без стоп-слов; всё, что рвёт последовательность, уходит в хвост
к спецкодам. Пороги и стоп-слова задаются константами `SPECIAL_CODE_MIN`
и `SPECIAL_LABEL_WORDS` в начале скрипта.

### 5. Оптимизация через `.smt`

* **Гриды.** По всем строкам одного грида собирается суммарный уникальный набор
  кодов, сортируется по правилам mtools (чистая шкала по возрастанию →
  спецкоды по возрастанию → `"Среднее"=m` в самом конце) и пишется в
  `<База>.smt` (например, `QB7.smt`). В `.adl` блоки ответов всех строк грида
  заменяются на `include QB7.smt`. В имени справочника остаётся одна точка —
  перед расширением: база `QC6.1` даёт `QC6.smt`.
* **Одиночные переменные.** Если у нескольких вопросов полностью совпали наборы
  ответов, блок выносится в общий `.smt` (имя берётся от первой переменной
  группы, например `QD1.smt`), а в `.adl` подставляется `include`.

## Принятые решения

Спецификация не фиксирует эти детали, они вынесены в начало скрипта и легко
меняются:

* спецкоды в шкальных гридах выгружаются в том же чистом формате
  `"Метка"=код`, что и сама шкала, — отличается только их позиция (хвост блока);
* общий `.smt` для одиночных дубликатов называется по имени первой переменной
  группы; если после отсечения лишних точек имя совпало с уже занятым
  справочником, добавляется суффикс `_2`, `_3` и т. д.;
* файлы пишутся с переводом строки CRLF (`\r\n`) — целевая среда mtools
  windows-ориентированная;
* двойные кавычки внутри меток заменяются на одинарные, чтобы не рвать
  синтаксис `"..."`.
